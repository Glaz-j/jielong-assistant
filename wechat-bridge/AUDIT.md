# 微信 4.x 只读接入候选

远程文件系统证据：C:/Program Files/Tencent/Weixin/4.1.15.56，2026-11-04。
旧 WeChatFerry 最新文档适配 3.9.12.51，因此未部署或注入它。

当前选取 wechatauto-replica 1.2.9 的 db.py，提交和原始文件校验见 vendor/jla_readonly/UPSTREAM.json，保留 Apache-2.0 许可。

静态检查发现：DB 模块 OpenProcess 仅申请 QUERY_INFORMATION 和 VM_READ；使用 ReadProcessMemory。未发现 WriteProcessMemory、远程线程、全局输入或前台激活调用。子进程用于进程列表/诊断，带 CREATE_NO_WINDOW。
完整原包的 __init__ 会导入 GUI 模块，因此不使用原包初始化，只保留 DB 文件，替换为不输出私人内容的 logger，并让密钥保护失败时拒绝明文缓存。

候选仍未通过远程实机读取；尤其 WAL 合并提交边界、增量延迟和版本兼容需要验证。此目录不进入现有对外验证包，也不启用自动提交。

probe.py 仅检查本人账号识别及文件传输助手最近 20 条消息是否能读取，输出数量/是否成功，不输出正文、账号 ID 或密钥。需要远程启动能力；此前 cmd2 多次超时。

第二轮审核发现并修正：上游 WAL 路径未限制最后提交边界，且失败会静默回退主库；现改用包含校验和的已提交快照合并，并逐页验证 SQLCipher HMAC。保留 MIT 快照实现许可证。部分消息分片读取失败现在抛错，不能用残缺结果推进游标；逐个登记已打开连接，后续分片失败会关闭已有连接。

快照当前采用“源文件有变化时完整认证重建、无变化时复用”的正确性优先实现，真实大库性能尚未测量，不能据此承诺 10 秒。异常时不发布新副本，旧副本保留但不作为本次成功读取结果。

receiver.py/listen.py 使用固定账号和群唯一 ID、首次启动基线、跨分片消息 ID 去重、先写文件事件后持久化游标。重启重放由消费者再按官网稳定编号去重。源事件以 wechat-db 标记，不再伪装成模拟事件；默认不开启该源。合成 Python XML→文件队列→Node 无窗口浏览器提交链路已通过，仍不是实机微信验收。
