## 当前行为

指定 QQ 群出现新的接龙管家官方 `/e/` 活动报名链接或 `/f/` 填表问卷链接后，程序在后台打开表单，只按固定字段匹配并填写。字段名称不能自定义：

| 字段 | 本次获准使用的虚构值 |
| --- | --- |
| 姓名 | 测试同学 |
| 单位 | 测试单位 |
| 职工号 | TEST0001 |
| 所属部门 | 测试部门 |

未知必填项、重名字段、无法匹配的选项、缺失资料会停止填写并显示原因。不会把“学号”当成“职工号”。可匹配同义字段，例如“工作单位”“工号”。官网授权保持未勾选；自动任务不会提交报名。人工核对后的提交仍有预览过期、表单变化、重复提交和结果不明保护，没有弹出的 JavaScript 确认框。

任务以活动编号去重。启动时已存在的链接只列出；每条新链接独立保留一个后台表单，最多保留 12 个。重启不会悄悄重报，内存草稿会标为“需重新填写”。

## 使用

1. 保持 QQ 已登录，为指定群打开独立聊天窗口，可置于后台。主窗口可切换其他会话。关闭独立窗口会暂停读取，不会弹窗重新打开。
2. 本机已为 `QQ群读取器.app` 配好辅助功能权限。不要移动、重新签名或重编译这个读取器，否则可能需要重新登记权限。
3. 打开应用，保存四项资料，输入群名，点击“开始监听并自动填写”。设置会保留到下次启动。
4. 群内发送新的官方活动链接，任务会自动排队。点击“查看填写结果”核对后台表单值。
5. 登录失效时任务显示“等待登录”，不会弹窗。只有主动点击“打开官网登录窗口”才显示浏览器；之后再次打开活动会恢复后台模式。

应用关窗后仍可后台运行；从菜单退出会停止由该应用启动的后端。若应用复用的是已由终端启动的后端，退出应用不会停止该终端服务，需要在原终端结束进程。

读取器只读取指定群窗口里已加载的消息，不读取聊天数据库，不会自动滚动历史消息，不修改 QQ、不注入进程、不发送消息。自动监听尚不等于接收任意群的完整消息流。文件上传、签名、定位、短信验证等复杂控件尚不支持。自动提交尚未实现。

## 开发和本机打包

Node.js + Playwright + Swift/AppKit/WKWebView。执行 `npm test`；目前 11 项测试通过，包括真实浏览器配合隔离的官网页面夹具（不是向官网提交测试）。执行 `./build-app.sh` 重新生成应用。

这是**当前 Mac 的开发版应用包，不是可分发的独立安装器**：仍依赖现有 Node、Playwright Chromium 缓存、项目 `data/` 和已有权限的读取器路径。移动到别的电脑需要安装依赖、重建读取器、重新授予权限并重新构建应用。应用包已编译和校验签名，原生窗口启动尚未单独验收；本轮不再弹出窗口打断用户。

新开发环境：`npm ci`、`npx playwright install chromium`、`./build-reader.sh`。重编译读取器会改变辅助功能权限身份；已有运行环境不要无故执行此步骤。

后端只绑定 `127.0.0.1`，写接口校验同源和本地随机令牌。`data/` 权限 700，资料、任务与提交记录 600。原始聊天通过临时命名管道在内存中传递，不写入聊天日志。登录会话只留本机 `data/browser/`。不要发布或提交 `data/`、截图中的私人会话或登录资料。

## 卡片适配进度（未完成真实端到端验收）

已添加 `cards.mjs`，支持 QQ miniapp JSON 的 `meta.detail_1.qqdocurl` 或 `url` 中明确给出的官方 `/e/`、`/f/` 地址，以及转义 JSON、CQ JSON 和 OneBot JSON 消息包装。只接受官方 HTTPS 目标，不根据卡片标题或零散活动编号猜地址。解析后进入同一任务队列并去重；未知跳转卡片会单独提示，不再被同一聊天里的旧链接掩盖。其他品牌的小程序不会产生接龙卡片告警。

这些测试使用合成消息夹具，不是 QQ 实际发出的卡片。当前签名读取器尚未证明能取得真实卡片 JSON。只显示标题的卡片、QQ 不透明短链仍未打通；没有安装协议插件、修改 QQ 或重新签名读取器。需要先定位一条真实接龙管家卡片，再验证接收端数据是否可用。
