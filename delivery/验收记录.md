# 接龙助手 1.0.0 验收记录

2026-11-04，北京时间。交付范围：Windows 上指定微信群接龙管家小程序卡片的后台自动填表。字段固定为姓名、单位、职工号、所属部门；首次由本人填写资料、登录并选群。

## 真实群与官网验证

环境：Windows 11 Pro、微信 4.1.15.56、Edge 156.0.4314.58。监听用户新建的三人测试群。仅使用自建免费活动及虚构资料“测试2／测试单位2／TEST0002／测试部门2”。

| 测试 | 微信消息时间 | 官网确认时间 | 完整时延 | 结果 |
| --- | --- | --- | --- | --- |
| 测试2-09，真实姓名／工作单位／工号／部门 | 13:52:44 | 13:52:46.352 | 2.352 秒 | 成功 |
| 测试2-07，姓名／单位／职工号／所属部门 | 13:58:37 | 13:58:39.058 | 2.058 秒 | 成功 |

- 时间基于微信库的秒级消息时间与同机官网成功确认时间，精度受消息时间粒度限制。样本只有两次，不是所有网络和平台状态下的性能保证；不承诺名额。
- 官网“查看数据”分别核对四项资料正确，各仅一条报名记录。
- 测试2-07 先于 13:54:58 发到文件传输助手，未触发报名；随后发入指定群才触发。
- 14:01:43 在指定群重发测试2-07，保留原成功记录，官网仍只有一条记录。
- 微信前台停留在文件传输助手，小程序停留在其他页面，指定群仍被后台读取。
- 另有测试2-08 乱序四字段在同一 Windows 实机上通过手动链接触发后台提交，用时 2.056 秒；此项不计微信群完整时延。
- 发卡步骤使用远程桌面；消息监听、卡片解析、填表和提交全部由固定本地程序完成，无 AI Computer Use 运行依赖。

## 后台与生命周期

- 只读接入微信原程序，不重新签名、不注入、不操作微信窗口。
- 读取组件实际识别原生 Windows 卡片的空 appid + 官方 username 形式，同时拒绝身份冲突；已修复 formdetail 路由识别。
- 实际选群 API 按群编号选择，刷新读取到新建群。每轮消息读取常见约 0.1 秒，部分轮次约 0.3 秒。
- 90 秒静态观察、180 秒切换前台观察、包含真实提交的 60 秒观察，应用及其子进程前台焦点命中均为 0；60 秒观察共 1183 个采样、3 次其他前台进程变化。此为采样验证，不等同于长期所有工作负载保证。
- 真实退出后 Node 和 Python 子进程均退出；隐藏重启恢复监听，个人资料、所选会话和报名记录保持不变。
- 不设置系统开机自启。关闭设置页后继续后台运行；退出后台后停止。

## 自动回归

- Node：53 项通过；Python：24 项通过。
- 34 种表单场景使用真实无窗口浏览器与隔离测试网页，不是 34 次官网报名。
- 正向：顺序变化、编号/空格标签、明确别名、文字/多行/电话控件、旧值覆盖、下拉/单选、可选备注、隐藏副本、只读且一致、已批准保存信息授权。
- 拦截：不明字段、缺失/重复字段、学号替代职工号、只读/禁用冲突、选项缺失/歧义/禁用、长度限制、页面改写职工号、附件、未知授权、截止、满额、收费、动态新增必填和服务器拒绝。
- 校验提交请求中的实际值，包含前导零职工号；同一官网编号更换短链接仍去重。未知提交结果不自动重试。
- 覆盖合成消息交接、同名群、无登录拦截、过期心跳、错误 PID、发现失败、在途任务退出、认证数据库/WAL 内容快照更新与一致性检查。

## 分发与适用边界

- 内置 Node v24.22.2、Python 3.13.17 Windows x64；依赖与运行时来源及哈希随包保留。
- Windows 原生验证包含运行时加载、DPAPI 往返、父进程等待句柄、无窗口 Edge、空白首次资料、保存虚构资料和未配置启动拦截。
- 白名单构建，不带开发者个人资料、登录态、密钥、聊天库、日志、远程调试服务。每个文件记录在 MANIFEST.json。
- 当前版本针对上述 Windows/微信环境；QQ、macOS、其他微信版本及连续数日运行未在本次最终验收覆盖。
- 首次必须本人登录微信和接龙管家。保存资料不能替代服务认证；登录失效需本人重新登录。
- 免费四字段范围外的复杂表单、验证码、收费和额外授权会停止处理，结果页显示原因。
